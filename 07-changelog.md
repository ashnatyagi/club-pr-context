### 2026-09-17 — Claude (with Ashna)
- **Root-caused the "QC feels too strict" complaint:** Flow B's Groq Vision QC only judges whether the burned-in club/event text is legible/not cut off — it never re-judges Ashna's pre-screened poster image itself. The real defect was Cloudinary's text overlay having no width limit, so long club+event names ran off the frame edge at the smallest font size. Fixed in Flow B's "Build Zoompan Video URL" node: the `l_text:` layer now carries `w_iw_mul_0.8,c_fit` so long text wraps within 80% of the image's own width instead of overflowing. Verified visually on a real long-name poster and a short-name poster (no regression). Published to Flow B (now **live**, not draft).
- **Found and fixed Flow A's Telegram trigger going silent:** no executions for 24+ hours (last run 15 Sep 13:17). Unpublished + republished Flow A to force n8n to re-register the webhook with Telegram's Bot API — confirmed fixed when 4 backlogged messages flooded in within the same second right after republish.
- **Found and fixed a Groq model access loss affecting all 3 AI vision calls:** `qwen/qwen3.6-27b` started returning "model does not exist or you do not have access to it" — hit Flow A's image tagging, Flow A's video tagging (`Groq Video Tag`), and Flow B's `Groq Vision QC Check` simultaneously, since all three share one Groq credential and model name. This explains earlier image-tagging failures too, not just video. Switched all three nodes to `qwen/qwen3.8-27b` (Groq's other current documented vision model) and republished Flows A and B. Verified live: retried the 4 backlogged executions against the fixed config — all 4 succeeded with correctly-tagged rows (confidence 0.95–0.98) in Sheet1.
- **Video tagging was broken by FOUR separate faults stacked on one another — all now fixed.** After the webhook + Groq-model fixes, videos still failed. The whole `Is Video For AI Tag?` **true** branch had never once executed in production, so every node on it carried an undetected fault. They could only be found one at a time, because each one hid the next:
  1. **Routing.** `Is Video For AI Tag?` sent every video to the **false** branch even though `source_type` was plainly `"video"`. Extracted the saved node JSON and checked both sides character-by-character — both were clean ASCII `video`, so whitespace/case/type were ruled out. Rebuilt the same condition, same data and same node config (`typeVersion` 2.3, `typeValidation: strict`, `caseSensitive: true`) in a throwaway workflow: it evaluated **true** there. The production node was therefore serving a stale compiled copy of an earlier version. Fixed by simplifying the condition back to `{{ $json.source_type }}` equals `video` and doing a clean re-save + publish (version `9b157ecb`), which forced the engine to recompile. An earlier "defensive" variant (`String(...).trim().toLowerCase()`) was **not** the fix and has been removed — it addressed a cause that did not exist.
  2. **Syntax error in `Build Thumbnail URL`.** Two stray `}` after the `return` statement made the whole Code node fail with `Unexpected token '}'`. Pre-existing and invisible, because the node had never run. Fixed in version `d2a6148a`; all six Code nodes in Flow A were then syntax-checked (the rest are clean).
  3. **Broken JSON body in `Groq Video Tag`.** The model value was missing its closing quote — `"model": "qwen/qwen3.8-27b,` instead of `"qwen/qwen3.8-27b",` — so the entire request body was invalid JSON. **This one was our own typo**, introduced during the qwen3.6 → qwen3.8 switch earlier the same day: all three Groq nodes were edited together, but only the two on the image path were verified live, because the video path was unreachable at the time.
  4. **`Groq Video Tag` body was in Fixed mode, not Expression mode.** `{{ $json.thumbnail_url }}` was therefore sent to Groq as literal text, and Groq replied `unsupported protocol: (only http and https are allowed)`. Its sibling on the image path (`HTTP Request`) was already in Expression mode, which is why only video was affected. Also lowered `max_tokens` from 2000 to 800: 2000 exceeds this Groq account's on-demand limit of **1000 output tokens per minute**, which returned `Request too large ... Limit 1000, Requested 1040`.
- **How fix 3 and 4 were verified:** rather than guessing again, the `Groq Video Tag` node was copied into a scratch workflow, fed a real Cloudinary thumbnail URL, and run for real. Groq returned a valid structured tag object (`vibe_tag: "lounge"`, `confidence: 0.1` — low only because that particular frame is dark). Both fixes were then applied to Flow A and published. The scratch workflows were archived afterwards.
- **Note on n8n retries:** "Retry with currently saved workflow" on this instance replays the **original execution's snapshot**, not the current one — three consecutive retries kept reproducing an already-fixed bug. Fresh webhook-triggered executions *do* pick up the new version (confirmed by execution #23052). **Do not use retry to verify a fix on this instance; use a fresh trigger or a scratch workflow.**
- Session notes/evidence for all of the above are also in the AI assistant's own memory (`/areas/pr-business-automation.md`) and in the persisted report artifact shared with Ashna.
